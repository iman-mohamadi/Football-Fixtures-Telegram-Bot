# Internationalization

Languages: **Persian (`fa`)** and **English (`en`)**.

## Architecture
```
src/i18n/
  index.ts          t(lang), digits(), normalizePersian(), language-picker text, default timezone by language
  locales/fa.ts     source-of-truth shape
  locales/en.ts     typed `typeof fa` → a missing/extra key fails `tsc`
```
- Every user-facing string lives in a locale file. Views call `m(user.lang).someKey` (or `t(lang)`); no handler contains `if (lang === 'fa')` text branches.
- Strings with parameters are functions (`notifReminderBody(match, mins)`), so word order can differ per language.
- The **only** bilingual text is the first-run language picker (`LANGUAGE_PICKER_TEXT`), because the language is not known yet.
- Competition names are data in `services/football/competitions.ts` (`nameFa`/`nameEn`). Team names are data in `services/teams/catalog.ts`.

## Conventions
- Keys describe meaning (`emptyLive`), not wording. Group related labels under `btn`, `statusLabel`, `notifKinds`.
- HTML parse mode: only `<b>`, `<i>`; always `esc()` dynamic text.
- Numbers shown to users go through `digits(lang, …)` (Persian digits for `fa`). Never apply it to IDs, callback data, or team names.
- Persian lines are prefixed with RLM (U+200F); Latin team names + scores are wrapped in LRI/PDI isolates so “A × B” and scores keep their order in RTL text.
- Persian separator between teams is `×`; English is `vs`.

## Adding a language
1. Add the code to `Lang`/`SUPPORTED_LANGS` and `DEFAULT_TIMEZONE_BY_LANG` in `src/i18n/index.ts`.
2. Create `locales/xx.ts` typed `typeof fa` (compiler lists everything missing) and register it in `locales`.
3. Add `{ lang: 'xx', label }` to `LANGUAGE_BUTTONS`, extend the database `CHECK (lang IN (...))` with a migration.
4. Add the Intl locale in `utils/time.ts` (`labelLocale`, `formatFullDate`).
5. Add Persian-style special handling only if the script needs it (digits, RTL).
6. `tests/i18n.test.ts` checks key parity and placeholder usage automatically.

## First-run flow
`/start` for a user whose `lang_selected` is false shows **only** the language picker (`ln:fa` / `ln:en`). Any other button or text returns the picker until a language is chosen. Selecting a language stores `lang`, sets `lang_selected = true`, and – *only this first time* – sets the initial timezone (`fa → Asia/Tehran`, `en → UTC`). The selection survives restarts (PostgreSQL). Later changes via Settings → 🌐 only update `lang`; favorites, timezone, display view, notification settings and match reminders are untouched.

## Dates, calendars, timezones
- Kickoffs are stored and passed around as **UTC ISO strings**. Conversion happens only at display time via `Intl` with the user's IANA zone.
- Language and timezone are independent (a Persian user in Berlin, an English user in Tehran).
- `fa` dates use the Jalali calendar (`fa-IR-u-ca-persian`): `جمعه، ۱۵ آبان ۱۴۰۵`; `en` uses Gregorian: `Friday, November 6, 2026`. Calendar choice never changes the instant. Verified in tests: 2026-11-06 = 15 Aban 1405, 2026-03-21 = 1 Farvardin 1405, 2026-03-20 = last day of Esfand 1404, and a 21:00Z kickoff is the next Jalali day in Tehran.
- Local day boundaries are computed per zone ([start, next start)), so DST days of 23/25 hours are handled (tested for Berlin and New York). Iran has no DST since 2022 (handled by the platform's tz database).
- Requires Node with full ICU (default in Node ≥ 13).

## Team localization
`src/services/teams/catalog.ts`:
- Entries have `fa`, `en`, English aliases (exact spellings providers use) and optional Persian aliases.
- Provider names are mapped by **exact normalized equality only**. "Esteghlal" and "Esteghlal Khuzestan" are separate entries; unknown names are shown as the provider gave them in both languages – never guessed.
- Aliases that two entries claim are discarded and reported through `AMBIGUOUS_ALIASES` (a test asserts none).
- Favorites of catalog teams use a provider-independent key (`tc:esteghlal`), so one favorite follows the team across providers.
- Search accepts Persian or English (Arabic ي/ك variants and ZWNJ are normalized) and only searches teams that play in the next 10 days (the shared cache window).
- `providerIds` exists for verified provider IDs; it is empty until verified against a live key.
- The catalog covers the Iranian clubs seen in the current league table and ~16 major world clubs. Extend it as needed – nothing else must change.

## Limitations
- Teams outside the catalog stay in Latin script in Persian mode.
- Competition logos/crests cannot be embedded in Telegram message text; they are stored in the model but not rendered.
